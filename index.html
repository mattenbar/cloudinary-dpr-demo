      02 / The important rule

      DPR changes the file.
      HTML controls the display.

      Both examples request the exact same 2× Cloudinary asset. Only one tells the browser the desired final display dimensions.

      Incorrect Missing display dimensions
      Intended display
      360 × 240 CSS px

      The browser uses the natural size

      Cloudinary returns 720 × 480 pixels. With no HTML width and height, the browser displays all 720 × 480 CSS pixels—twice the intended dimensions.

      Correct Final dimensions declared

      2× pixels, displayed at 1× size

      The same 720 × 480 output is constrained to 360 × 240 CSS pixels. On a 2× screen, each CSS pixel gets four image pixels for a crisp result.

      Delivered dimensions — Displayed dimensions — Effective DPR — Original file size — Derived file size —
      <img src=".../dpr_2.0/f_auto/q_auto/..." width="360" height="240">

      The URL’s width and height are logical dimensions. DPR multiplies the delivered pixels. The image tag’s dimensions preserve the intended layout.

      1

      Enable the hints

      Delegate Sec-CH-DPR for density and Sec-CH-Width for responsive width to your Cloudinary origin.

      2

      Choose the sizing path

      Use fixed dimensions with dpr_auto for a known slot. For a fluid slot, use w_auto with a fallback width and dpr_auto.

      3

      Describe the layout

      Keep width and height attributes for layout stability. Add an accurate sizes attribute whenever you use w_auto.

      Advanced responsive sizing

      For fluid layouts, automate width too.

      The fixed 360 × 240 examples above deliberately isolate DPR. In a production layout where the image width changes, w_auto can also match the delivered resource to the space available.

      • Use w_auto:40:360 so widths are rounded in 40-pixel steps and 360 pixels is available as a no-hint fallback.
      • Use an aspect ratio such as ar_3:2 to establish height. Cloudinary does not support h_auto as an automatic-height URL transformation.
      • CSS height: auto is still useful for fluid rendering, but it is separate from the Cloudinary delivery transformation.
      Responsive Cloudinary URL
      https://res.cloudinary.com/doxfstysv/image/upload/ar_3:2,c_fill,g_auto/c_limit,w_auto:40:360,dpr_auto/f_auto/q_auto/v1783615661/SpacEx_Getty-1360560315_m8u9dx.jpg
      Matching display markup
      <img src=".../c_limit,w_auto:40:360,dpr_auto/f_auto/q_auto/..." sizes="(max-width: 360px) 100vw, 360px" width="360" height="240" style="width:100%;max-width:360px;height:auto" alt="">

      Adjust sizes to the real CSS. The example describes an image that fills the viewport up to a 360-pixel maximum. A different grid or container needs a different media condition.

      i

      Know the fallbacks

      Server-side client-hint detection currently works in Chromium-based browsers. Without a hint, dpr_auto becomes 1× and bare w_auto may deliver the original dimensions. Include a width fallback, or use native srcset and sizes when broader browser support is required.
